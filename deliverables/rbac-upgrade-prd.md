# 科诺美线索跟进管理系统 — 分级权限（RBAC）与审计日志增量 PRD

## 1. 项目信息

- **Language**: 中文
- **Programming Language**: 沿用现有技术栈（单页 index.html 前端 + EdgeOne 边缘函数 API + EdgeOne Blob 存储），不引入新框架
- **Project Name**: chromai_leads_rbac_upgrade
- **原始需求复述**：在现有线索跟进管理系统（leads 2282 条 + fups 250 条，暗色主题看板）基础上，将单一密码门禁（chromai2019）升级为「邮箱 + 统一密码」的三级账号体系（管理员 3 人 / 大区总 3 人 / 销售 7 人），按角色对看板、市场留资清单、MQLs 做数据行级过滤与编辑权限控制；同时为管理员提供登录与数据修改的审计日志查看能力。

## 2. 产品定义

### 2.1 Product Goals

1. **数据可见性按岗隔离**：管理员看全量、大区总看本大区、销售只看本人名下，三个角色的看板/留资清单/MQLs 视图严格一致地套用同一套过滤规则，杜绝越权读取。
2. **编辑权限与可见范围一致**：用户只能编辑自己可见范围内的数据，且"负责人/负责大区"字段受控，防止数据归属被随意篡改。
3. **操作可追溯**：管理员可在系统内查看完整的登录日志与数据变更日志（谁在什么时间改了哪条记录的什么字段），满足内部管理审计诉求。

### 2.2 User Stories

1. As a **管理员（于翠/汪琼/张欣）**, I want 登录后看到与现在完全一致的全量看板与两张数据表, so that 可以统管全盘业务并处理跨区数据调整。
2. As a **管理员**, I want 在系统中打开"日志"页面查看所有账号的登录/登出/新增/编辑/删除记录, so that 出现异常数据时能快速定位责任人和操作时间。
3. As a **大区总（汤显义/穆忠仁/管能）**, I want 登录后只看到本大区的线索、MQLs 和看板统计，并能编辑本大区内任意销售名下的记录, so that 我可以管理区域业务而看不到其他大区的数据。
4. As a **销售（王远帅/高丹枫/黄江锐/王泽/胡雨来/高雷/刘力瑞）**, I want 登录后只看到和编辑自己名下的线索与跟进记录，看板只统计我的数据, so that 我专注自己的客户且不被无关数据干扰。
5. As a **任一用户**, I want 用公司邮箱 + 统一密码登录、可主动退出、会话长期保持不频繁掉线, so that 日常使用顺畅且公共电脑上能安全退出。

### 数据范围判定规则（关键决策，建议如下）

- **线索（leads）行归属**：以行内"负责大区"字段判定大区归属，以"负责人"字段判定个人归属。
  - 销售可见：`负责人 == 本人姓名`
  - 大区总可见：`负责大区 == 本人姓名`（该列存的是大区总姓名）
- **MQLs（fups）行归属**：fups 行只有"线索编号 + 负责人"两个可判定字段，**建议两者结合**：
  1. 主规则：通过"线索编号"关联到 leads 行，继承该线索的大区/负责人归属；
  2. 兜底规则：若线索编号为空或关联不上（历史脏数据），按 fups 行自身"负责人"字段判定——销售：`负责人 == 本人`；大区总：`负责人 ∈ 本大区销售名单 ∪ {本人}`。
  - 这样可保证"线索已被改派到其他大区"时跟进记录随线索走，同时兜住脏数据不漏。
- **看板口径**：所有 KPI 卡与图表（留资总数/MQLs/待跟进/SQL/流失/各大区/各销售/来源/行业/阶段分布等）均基于上述过滤后的数据集计算，不做"全量统计+局部展示"。

## 4. 技术规范

### 4.1 Requirements Pool

**P0（Must have）**

1. 邮箱 + 统一密码（chromai2019）登录页：13 个账号白名单校验，邮箱不区分大小写；替换现有单口令门禁（见 5.1 替换方案）。
2. 登录会话：签发会话令牌（token），前端存储于 localStorage，所有 API 请求携带；登出按钮清除会话并记录日志。
3. 三级角色数据过滤：登录后看板、市场留资清单、MQLs 三个视图按第 3 节规则过滤；**过滤必须在后端 API 层执行**（前端过滤可被绕过，不可接受）。现有 GET /api/leads、/api/followups、/api/flowchart、/api/mql 均需按 token 角色裁剪返回数据。
4. 写权限校验：POST 写接口校验 token，仅允许修改/新增自己可见范围内的记录；越权写入返回 403。
5. 字段锁定规则：
   - 销售：新增/编辑线索时"负责人"字段**锁定为本人**、"负责大区"锁定为所属大区；**允许将本人名下线索改派给同大区其他销售**（下拉仅限本大区销售名单，改派后该线索从自己视图消失）。
   - 大区总：可在本大区内自由改派（负责人下拉为本大区销售+本人，负责大区锁定为本大区）。
   - 管理员：不受限。
6. 审计日志（记录侧）：后端记录以下事件——**登录成功、登录失败、登出、新增、编辑（含字段级 diff：字段名/旧值/新值）、删除、数据导入（批量新增）**。日志字段建议：`时间 / 用户邮箱 / 用户姓名 / 角色 / 事件类型 / 对象类型(lead|fup|session) / 对象ID(线索编号或跟进编号) / 变更明细(字段:旧值→新值) / 结果(成功|失败)`。IP 如边缘函数可获取则一并记录。
7. 审计日志（查看侧）：管理员专属"日志"Tab，支持按时间/用户/事件类型筛选与倒序浏览，分页加载。
8. 现有 chromai2019 单口令门禁移除：登录页即新门禁，旧口令逻辑删除；部署切换期间保证已登录用户不丢数据（无服务端会话状态下无迁移成本）。

**P1（Should have）**

1. 会话保持策略优化：token 有效期 7 天，滑动续期（每次有效请求顺延）；连续 7 天未操作需重新登录。设备端可勾选"退出登录"。
2. 导出权限控制：如页面有导出/复制功能，导出内容同样套用行级过滤，且导出行为记入日志。
3. 账号管理简易入口：管理员可在日志 Tab 旁查看 13 个账号的角色配置（只读展示即可，编辑改配置走代码/配置变更）。
4. 日志保留策略：至少保留 12 个月，超期归档或清理。

**P2（Nice to have）**

1. 首次登录强制修改个人密码（解决统一密码的安全隐患，本期明确不做，仅记录）。
2. 登录失败锁定：同一邮箱连续 5 次失败锁定 15 分钟。
3. 日志导出 CSV。
4. 大区总可将线索改派给其他大区（需管理员审批或仅管理员可操作）。

### 4.2 UI Design Draft

- **登录页**：沿用暗色主题；居中卡片，两个输入框（邮箱、密码）+ 登录按钮；错误提示（"邮箱或密码错误"）不区分哪种错误；页脚保留系统名称。替换现有单密码输入框。
- **顶栏**：右侧显示当前登录人「姓名 · 角色」（如"汤显义 · 大区总"）+「退出登录」按钮。
- **主界面**：现有看板/留资清单/MQLs 三个 Tab 不变，数据按角色过滤；销售角色的"负责人"筛选器隐藏或禁用（无意义）。
- **日志 Tab**：仅管理员可见，放在现有 Tab 序列末尾（不另起独立后台页面，降低实现成本）；表格列：时间/用户/角色/事件/对象/变更明细/结果；顶部筛选条（时间范围、用户下拉、事件类型下拉）。
- **编辑弹窗**：根据角色禁用"负责人/负责大区"字段（销售改为下拉仅同大区可选；大区总下拉限本大区；管理员全量可选）。

### 4.3 Open Questions

1. **会话时长**：建议 token 7 天滑动续期是否接受？还是希望更短（如 24 小时）？（默认按建议执行）
2. **销售改派**：确认"销售可改派给同大区同事"是否符合管理意图？若不允许，则销售负责人字段完全锁定。
3. **穆忠仁大区**：目前无下辖销售账号，穆忠仁登录看到的就是自己名下数据——确认无需为其销售预留账号。
4. **历史数据中"负责人/负责大区"为空的线索**：默认仅管理员可见可编辑（归入"未分配"），是否同意？
5. **删除操作**：现有系统是否已有删除入口？若无，"删除日志"仅为预留；是否需要在本次为管理员开放删除权限？
6. **导入/导出**：现有系统若无批量导入导出入口，相应日志项降级为预留，请确认。
7. **日志查看粒度**：管理员是否需要看到"登录失败"记录（用于安全监控）？默认记录并展示。
8. **多端同时登录**：是否允许同一账号多端在线？默认允许（不做单点踢出）。

## 5. 关键决策建议汇总

| 决策点 | 建议 |
|---|---|
| 会话保持 | 7 天有效 + 滑动续期，localStorage 存 token，显式"退出登录"按钮 |
| 销售"负责人"字段 | 新增时锁定为本人；允许改派给同大区销售（改派后移出自己视图） |
| 大区总数据范围 | 线索按"负责大区"字段；MQLs 优先按关联线索归属，关联不上按行内"负责人 ∈ 本大区名单"兜底 |
| 日志事件 | 登录成功/失败、登出、新增、编辑（字段级 diff）、删除、导入；查看侧仅管理员 |
| 日志入口 | 主界面新增"日志"Tab（仅管理员可见），不做独立后台 |
| 统一密码安全 | 本期维持 chromai2019；首次登录强制改密列为 P2 后续迭代 |
| 旧口令门禁 | 整体移除，登录页替换之；无服务端会话状态，无迁移成本 |
