系统简介

科诺美（Chromai）线索跟进管理系统是一套面向 HPLC 行业市场线索全生命周期管理的轻量级 CRM 工具。系统以单一 HTML 文件为载体，无需安装，浏览器打开即用，数据存储在本地 localStorage 中，支持 CMS 后端同步。

核心特点

  • 零依赖 — 纯 HTML + CSS + JavaScript，无需数据库即可运行
  • 5 个功能模块 — 数据看板 / 线索池总表 / 跟进记录 / 流程示意图 / MQL评分标准
  • 全字段可编辑 — 所有 Tab 的文字内容均可点击直接编辑
  • 增减列管理 — 支持动态添加和删除自定义列
  • CMS 后台 — Express.js 后端提供 REST API 和数据管理
  • 多平台部署 — 支持 CloudStudio / GitHub / Vercel 一键部署

技术栈

层级技术说明
前端HTML + CSS + Vanilla JS单文件，无框架依赖
存储localStorage浏览器本地存储，STORAGE_KEY 版本化管理
后端Express.js (Node.js)REST API + JSON 文件存储
部署Vercel / CloudStudioServerless + 静态托管

快速开始

方式一：直接打开 HTML

  1. 双击 index.html 文件，用浏览器打开
  2. 系统自动加载默认数据，即可开始使用
  3. 所有修改点击右上角 💾 保存 按钮持久化到浏览器本地

方式二：启动 CMS 后端

# 进入项目目录 cd chromai-leads-cms # 安装依赖 npm install # 启动服务 npm start # 访问 # 主系统: http://localhost:3000 # CMS后台: http://localhost:3000/admin.html
💡 推荐使用方式二，可以享受 CMS 后端的数据管理和 API 服务。

数据看板

数据看板是系统的首页，自动从线索和跟进数据中计算统计指标。

KPI 卡片

  • 线索总数 全部线索数量
  • 已跟进 有销售反馈的线索数
  • 未跟进 阶段为 Raw 的线索数
  • MQL 市场合格线索数
  • 流失 流失/回收阶段线索数

分析板块

  • 各销售跟进效果分析 — 按销售统计跟进数和转化情况
  • 各大区跟进情况 — 按三大区（汤显义/管能/穆忠仁）统计
  • 活动来源分析 — 按活动来源统计线索量和跟进率
  • 全部线索阶段分布 — 各阶段线索数量分布
💡 以上分析板块已过滤"同业公司"和"其它"行业的线索，避免干扰统计。

线索池总表

线索池是系统的核心数据表，包含全部线索信息。

列结构

列号列名类型说明
0线索编号文本唯一标识，如 CPM-2026-0001
1线索来源下拉展会/直播/官网咨询/转介绍等
2活动名称文本如 CPHI2026、川检会等
3-9客户信息文本公司名/联系人/职位/电话/邮箱/行业/地域
10企业规模下拉50人以下 ~ 1000人以上
11当前阶段下拉Raw/MQL/SQL/商机推进/报价与谈判/成交签约/流失回收
12线索评分文本0-100 分
13负责人下拉下辖销售姓名
14负责大区文本大区总姓名
15-16创建日期/备注文本创建时间和补充说明

筛选功能

  • 阶段筛选 — 下拉选择特定阶段的线索
  • 销售筛选 — 下拉选择特定负责人的线索
  • 编号检索 — 输入线索编号模糊搜索

新增线索

点击顶部 + 新增线索 按钮，在弹窗中填写信息，系统自动生成线索编号。

跟进记录

跟进记录追踪每次销售跟进活动，与线索池通过"线索编号"关联。

核心功能

  • 线索编号链接 — 点击线索编号蓝色链接，自动跳转到线索池并筛选高亮目标行
  • 新增跟进 — 点击 + 新增跟进 为当前线索添加跟进记录
  • 删除记录 — 每行末尾有 ✕ 按钮可删除该条跟进
  • 负责人同步 — 保存时自动将跟进记录的负责人同步为线索池中的负责人

跟进内容格式

[销售反馈] 客户对制备色谱感兴趣，预算30万 | [MQL评分] 75分

流程示意图

展示 Leads Follow 全流程，4 个时期 8 个阶段 + 流失回收分支。

四个时期

  • 获取期 线索获取 → 线索录入与清洗
  • 评估期 线索评分分级 → MQL 线索培育
  • 转化期 SQL 销售确认 → 商机推进
  • 成交期 报价与谈判 → 成交签约交付

编辑方式

所有文字（标题、阶段名称、负责部门、关键动作、转化标准、SLA、周期）均可点击直接编辑。修改后点击 保存 按钮持久化。

MQL 评分标准

线索合格度评分模型，满分 100 分，3 个维度。

维度满分评分项
行为评分40分下载白皮书(10) / 参会(10) / 试用申请(15) / 多次访问(5)
企业属性30分目标行业(15) / 企业规模(10) / 地域覆盖(5)
采购信号40分预算明确(15) / 时间表(10) / 决策人(15)
💡 综合评分 ≥ 60 分 → 升级为 MQL → 移交销售中心（SLA ≤ 48h）

编辑与保存

表格编辑（线索池 / 跟进记录）

  1. 点击单元格进入编辑模式（蓝色边框高亮）
  2. 下拉列直接选择，文本列直接输入
  3. 按 Enter 或点击其他位置确认编辑
  4. 编辑后保存按钮变为 💾 保存 *（带星号提示）
  5. 点击 保存 按钮持久化到 localStorage

流程图 / MQL 编辑

  1. 直接点击文字区域即可编辑（contentEditable）
  2. 编辑时显示蓝色高亮边框
  3. 切换 Tab 或关闭页面时自动收集编辑内容
  4. 点击 保存 按钮持久化
⚠️ 未保存的修改在刷新页面前会弹出确认提示。建议养成及时保存的习惯。

增减列管理

系统支持在线索池总表和跟进记录中动态添加和删除自定义列。

添加列

  1. 点击表格上方 + 添加列 按钮
  2. 在弹窗中输入新列名称
  3. 新列追加到表格末尾，所有行自动填充空值
  4. 新列的单元格可直接点击编辑
  5. 点击 保存 持久化

删除列

  • 自定义列的表头有红色 ✕ 按钮（hover 时显示）
  • 点击 ✕ 并确认后删除该列及其所有数据
  • 系统列不可删除（线索池前17列、跟进记录前15列为系统列）
💡 列管理工具栏会显示当前列数统计：共 X 列（系统 Y + 自定义 Z）

复制粘贴

单格操作

  • Ctrl+C — 复制当前单元格
  • Ctrl+V — 粘贴到当前单元格

批量操作

  • Shift+点击 — 选择矩形区域（从锚点到点击位置）
  • Ctrl+C — 复制选区
  • Ctrl+V — 粘贴到选区起始位置
  • Delete — 清空选区内容

行列调整

  • 列宽调整 — 鼠标移到列头右边框，出现蓝色拖拽条，拖动调整宽度
  • 行高调整 — 鼠标移到行底部边框，出现蓝色拖拽条，拖动调整高度
  • 调整结果自动保存

导出 CSV

点击顶部 导出CSV 按钮，系统将线索池和跟进记录分别导出为 CSV 文件。

💡 CSV 文件可用 Excel / WPS 直接打开，方便离线分析或汇报。

CMS 管理后台

访问 /admin.html 进入 CMS 管理后台。

功能

  • 系统状态 — 实时显示线索数、跟进数、服务状态
  • 数据导出 — 一键导出全部数据为 JSON 文件
  • 数据导入 — 从 JSON 文件导入数据（覆盖服务器数据）
  • 浏览器同步 — 将浏览器 localStorage 数据上传到服务器，或反向同步
  • API 文档 — 在线查看所有 API 接口
💡 CMS 后台适用于多人协作场景：先在本地编辑数据，然后同步到服务器供团队访问。

API 接口

方法路径说明
GET/api/status系统状态
GET/api/leads获取全部线索
POST/api/leads保存全部线索
POST/api/leads/add追加一条线索
PUT/api/leads/:index更新指定线索
DELETE/api/leads/:index删除指定线索
GET/POST/api/followups跟进记录 CRUD
GET/POST/api/flowchart流程图数据
GET/POST/api/mqlMQL评分数据
GET/api/export/all导出全部数据
POST/api/import/all导入全部数据

示例：获取线索数据

fetch('/api/leads') .then(r => r.json()) .then(data => console.log(data))

本地部署

# 1. 进入项目目录 cd chromai-leads-cms # 2. 安装依赖 npm install # 3. 启动服务 npm start # 4. 访问 # 主系统: http://localhost:3000 # CMS后台: http://localhost:3000/admin.html

CloudStudio 部署

  1. 在 CloudStudio 创建新工作空间
  2. 上传项目代码或将 GitHub 仓库关联到工作空间
  3. 在终端执行 npm install && npm start
  4. 系统在端口 3000 启动，通过 CloudStudio 预览链接访问
💡 CloudStudio 适合开发调试，支持实时编辑和预览。

GitHub + Vercel 部署

1. 推送到 GitHub

# 初始化 Git 仓库 cd chromai-leads-cms git init git add . git commit -m "科诺美线索管理系统 v1.0" # 关联 GitHub 仓库 git remote add origin https://github.com/你的用户名/chromai-leads-cms.git git branch -M main git push -u origin main

2. 部署到 Vercel

  1. 访问 vercel.com 并登录
  2. 点击 New Project → 选择 GitHub 仓库 chromai-leads-cms
  3. 框架预设选择 Other（自动检测）
  4. 点击 Deploy，等待部署完成
  5. 部署成功后获得 https://chromai-leads-cms.vercel.app 类似的访问地址
💡 Vercel 会自动识别 vercel.json 配置，api/ 目录下的文件自动部署为 Serverless Functions。

3. 持续部署

之后每次 git push origin main，Vercel 会自动重新部署。
